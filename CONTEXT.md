# Development handoff

Updated 2026-11-16. `README.md` holds the product brief and run instructions. The code is the source of truth if these notes become stale.

## Latest change: batched coverage and separate main ideas

- The study workspace now places **Sources (n)** in the space header beside More actions. The separate Choose sources picker was removed. Browser quiz and deck generation use all active documents; removing a document in Sources excludes it from future generation without changing saved results. The server still accepts explicit `documentIds` for API compatibility. When active sources exceed a format's count or character limit, the UI directs the learner to remove sources.
- Main ideas, Quiz, and Flashcards now share the same study-pane layout and header refresh icon. Main ideas refreshes its all-active-documents summary; Quiz and Flashcards create new saved results using all active sources, with earlier results in their pickers. The workspace header keeps the combined Generate action only when neither quiz nor deck exists. Disabled icon states follow each format's source and character limits. Accessible labels and tooltips explain each icon's action.

- Quiz and deck generation still start with one whole-selection request. Missing sources are now handled together in a structured batch with a required output field and document-specific source-block IDs for each missing document. Valid items are kept, and remaining invalid or duplicate items get one more batched attempt. The final coverage gate still refuses to save a partial result. Each format now makes at most three model calls for a result regardless of the number of documents within its ten/twenty-source limit. In the browser, larger active sets require removing sources; linked result series are not implemented yet.
- Main ideas are no longer generated as part of a new quiz. POST `/api/spaces/:id/summary` makes an independent model call for all active documents and saves a space-level summary with a document ID snapshot, a short synthesis, and cited ideas for each source. Longer documents are divided into up to eight successive parts; the schema and validator require an idea citing a block from each part. This gives source and section spread, not proof that every important concept is correct or present. Main ideas is now the first study mode and opens by default, followed by Quiz and Flashcards; it can be refreshed separately and shows when its source snapshot is stale. Starting quiz/deck generation also requests a missing or stale summary when all active sources fit the 40,000-character limit. Old quiz overviews remain readable in a collapsed disclosure.
- The summary route lives in `routes/spaces.js`, summary request construction in `model.js`, and summary validation in `study.js`. `tests/summary.test.js` covers source and section spread, failed validation, and refreshing; UI tests cover the independent summary result. `npm test`, `npm run typecheck`, and `npm run build` passed. A read-only live model check with the six active React documents returned six validated summary sections with 3, 2, 2, 2, 2, and 8 ideas; a separate three-document batched quiz-coverage check returned three valid source-specific questions. Neither live check saved study data.

## Earlier change: enforced per-source item coverage

- New quiz and deck generation saves only if every selected active document has at least one structurally valid cited item. A failure returns 422 naming uncovered documents, includes details for completed model calls, and saves no partial result for that format. Quiz and deck generation remain independent, so the other format can succeed. Batched fill requests now replace the earlier per-document fill strategy.
- Length-based targets now have a floor of one item per selected document. Selections above ten documents for a quiz or twenty for a deck are rejected by the API and disabled in the browser, while the 40,000-character limit still applies. Single-document compatibility requests retain their saved `documentId` shape and now carry the cited document ID on generated items. Earlier saved results, including those with incomplete coverage, remain readable.
- `app/api/_server/coverage.js` coordinates fill requests and final citation checks. `tests/source-coverage.test.js` covers successful fills, failed validation with no save, and document-count limits; `tests/space-generation.test.js` covers a seven-document snapshot. Source citation proves only that an excerpt comes from the cited document, not that the answer is correct or that its main concepts are fully covered.

## Earlier change: space-level study material

The server checks cited-document coverage and fills missed sources in batches as described above. Saved results show covered and uncovered source names, including older partial results; multiple successful API requests and their per-call usage remain inspectable. `tests/source-coverage.test.js` covers focused API requests, and `tests/ui.test.tsx` covers all-active browser generation and coverage display.

- Generation uses length-based targets: one quiz question per 2,500 source characters, up to ten; one card per 1,250 characters, up to twenty, with a floor of one item per selected document. Each format accepts fewer items from the first model response and fills uncovered sources in batches. Structured outputs use arrays, with local count, content, citation, and duplicate checks. Existing saved three-question quizzes and five-card decks remain readable and usable. Card edit/review routes accept IDs through twenty. These ratios are starting heuristics, not quality thresholds; evaluate them with varied source density and live model responses.

- Removed the earlier six-document generation cap. Generation requires at least one active document and at most 40,000 characters total; format-specific limits now allow up to ten selected sources for a quiz or twenty for a deck. The Sources drawer displays active document count and warns when characters exceed the limit. The browser and server enforce the same character rule; API and UI tests cover more than six documents and character-limit recovery.

- Sources show active document count and usage against the 40,000-character generation limit, plus a warning when it is exceeded. A document can be removed from active sources without deleting its text or existing quizzes/decks; removed documents appear in a collapsible section where they can be restored or permanently deleted. Generation and space-list counts use only active documents. Permanent deletion cascades to any saved run or deck that references the document, including multi-document results, and the UI confirms affected counts. Older saved documents without `removedAt` remain active. The new document PATCH and DELETE routes live in `routes/spaces.js`; `generationDocuments` excludes removed sources. API and UI tests cover the flow.

- Space management now supports rename, archive/restore, and permanent delete through `PATCH`/`DELETE /api/spaces/:id`. List summaries include `archivedAt` and saved-content counts; older spaces without `archivedAt` count as active. `app/_study/space-actions.tsx` owns the shared row/workspace menu and rename/delete dialogs. Active and archived spaces are separate list views. Archived rows are static and offer management actions without opening the workspace. Action success banners and the archive Undo snackbar were removed. Direct links to archived spaces remain readable, but document upload, generation, quiz answer/practice, and flashcard edit/review writes are rejected by the routes and disabled in the browser. Deleting a space removes its nested data from `data/spaces.json` and invalidates its hash link.

- The primary navigation now has two levels: spaces list → study workspace. Clicking or creating a space opens its workspace immediately. **Sources** opens a right-side overlay drawer for document upload, search, and a read-only document list without pushing the study content down. Document preview and its expand control were removed. An empty space opens Sources automatically. `#space-id` now opens the workspace; older `#space-id/study` and `#space-id/document-id` links still work, with the latter opening Sources but not a preview.
- The Sources drawer uses Material UI's temporary right drawer with a backdrop, close button, and standard Escape dismissal. The rebuilt production page was checked in a browser with the list-only rows. `npm test`, `npm run typecheck`, and `npm run build` passed.

- New quiz and deck requests without `documentId` use every active document currently in the space, capped at 40,000 characters total. The browser sends these space-level requests from the study view. Each format remains an independent request, so partial success is retained.
- New runs/decks save `documentIds` as a snapshot. Every generated question/card saves its cited `documentId` and an excerpt checked against that document. Adding another document does not alter saved material. The coverage gate guarantees one cited item per selected document in newly saved results, but does not guarantee coverage of every concept.
- Quiz and deck pickers show results across the space. Earlier results with a single `documentId` remain readable and answerable; the old API request shape still works for compatibility.
- `tests/space-generation.test.js` covers two-document generation, citations, and saved snapshots. `npm test` and `npm run typecheck` passed after the change.

## What exists

- A local Next.js App Router and React TypeScript app at `http://localhost:3000`. Next.js Route Handlers serve `/api` from the same process. Node.js 22.12 or later is required. `npm start` requires `npm run build` first.
- A learner creates a named **study space**, adds one or more `.txt` or `.md` documents, and generates quizzes and decks from all active documents currently in the space or a selected subset. Each document must contain 120–20,000 characters; generation accepts up to 40,000 characters total and at most ten selected documents for a quiz or twenty for a deck.
- For a space without either format, the primary Generate action starts independent quiz and flashcard requests using its current documents, plus a separate summary request when needed. If one fails, successful results stay saved and the missing format can be generated separately. Independent **Generate quiz/flashcards**, **New quiz/deck**, and **Refresh main ideas** actions remain available. Quiz generation requests up to ten four-option questions, with the exact target based on source length; missing sources may require one or two batched fill calls. Quiz selections are checked locally; missed questions can be practiced in a fresh round.
- Flashcard generation makes a separate OpenAI call for up to twenty cards citing documents in the space, with the exact target based on source length. Cards have editable questions and answers and a displayed source excerpt derived from the cited document. The learner reveals each answer, rates Again or Good, and can review Again cards or all cards in another round. Edits, ratings, rounds, and history persist locally; reviewing makes no model call.
- The browser opens on a searchable list of study spaces. A space opens its study workspace directly on Main ideas. The optional Sources drawer contains the add-document form, search, and document list; document text is not previewed. Generation uses the whole space by default. A Main ideas/Quiz/Flashcards switch shows one mode at a time, and a picker selects one saved run or deck when there are multiple in the space. Quiz practice shows the next unanswered question and the latest answered question with feedback; earlier answers use Material UI Accordions.
- Study spaces, document text, sessions, decks, quiz selections, flashcard reviews, explanations, request bodies, and usage are saved locally in ignored `data/spaces.json`. The app starts at the spaces list unless a URL hash names a valid space or document. Saved data survives server restarts. Earlier open-ended sessions remain readable and answerable.
- New quizzes cite numbered source blocks, and the server derives displayed excerpts from the uploaded document rather than trusting model-written quotes. Invalid quiz structure produces a retry message while still showing API usage and estimated cost for that call. Legacy open-ended responses still use exact-quote validation. The API key remains server-side.
- **View API request** shows the JSON body and per-call token usage. Standard `gpt-4o-mini` cost is estimated; other models show usage without a price estimate.

## Decisions and boundaries

1. A **study space** is the lasting container. A new **study session** is one generated set of multiple-choice questions using a snapshot of the space's current documents. A learner can start more sessions in the same space. Earlier single-document sessions remain supported.
2. Browser file selection reads `.txt` and `.md` as text and posts the text to the local server. The server validates the extension and length and saves an immutable copy. The initial 6,000-character cap rejected a real 7,013-character React lifecycle note, so the bounded limit is now 20,000 characters. There is no PDF extraction, cross-document retrieval, account system, or hosted deployment yet.
3. The store is a single local JSON file with writes serialized within the process and replaced atomically. This is suitable for one Next.js process with persistent local disk, not multi-instance deployment. `STUDY_DATA_DIR` can override the storage directory for tests.
4. New saved runs and decks record the immutable document IDs used at generation, so adding a document later does not change past questions or feedback. Earlier runs/decks keep their single `documentId`. Quiz attempts record a round number; the current round and its question IDs are saved on the run. A completed question cannot be resubmitted in that round. Earlier quiz attempts remain available under Previous rounds. Legacy quiz attempts without a round number count as round 1; older open-ended runs retain their original reattempt behavior.
5. OpenAI requests set `store: false`. The app still saves source text and the request body locally; users should not test with confidential workplace material. A space can be permanently deleted from its More actions menu. Deleting `data/spaces.json` erases all local study data.
6. The prior `/api/session` and `/api/answer` routes remain for compatibility and their existing tests, but the browser uses `/api/spaces` routes.
7. Removed the "Start with" dropdown because summary and explanation had no meaningful difference beyond a model style label. Main ideas now have their own space-level generation and are the first selectable study mode. Previously saved run overviews remain readable in a collapsed disclosure.
8. Replaced the browser's open-ended question flow with multiple-choice quizzes. A generation call supplies four distinct options, one answer key, a short explanation, and a source-block ID per question. The server validates the structure and block ID, derives the displayed excerpt from the document, then grades selected option indexes locally. New responses use a variable-length question array with local count checks; the older fixed three-question result motivated the original schema design. This removes per-answer model calls for new runs. A valid block reference does not prove the generated key or explanation is correct; review examples with real material before treating scores as reliable.
9. Flashcard decks are independent of quiz runs. New decks use a snapshot of all current documents in the space; older decks retain their single-document source. Initial generation calls both routes, and each request validates and saves separately. A deck has one to twenty editable cards and saved review rounds. The server accepts one Again/Good rating per card in a round; a completed round can start again with only Again cards or with all cards. Edits preserve card IDs and review history. Answer reveal is browser state; the server cannot verify that a learner revealed before rating. Source-block validation proves the displayed excerpt belongs to the cited document, not that the answer is correct. Spaced scheduling and Anki export are deferred.
10. Removed the misleading per-question **Try again** submit button. After a quiz answer, the selected option and feedback remain visible and the options are locked. When the round is complete, **Practice missed questions** starts a new round containing only questions missed in the current round, with selections and feedback cleared. The practice round is local and does not generate new questions or call OpenAI.
11. Originally grouped API runtime files under `server/` and behavior tests under `tests/`, with HTTP routes split by workflow. The API modules now live under `app/api/_server/`; the route functions return Web `Response` objects or `null` when unmatched. The store still writes to root `data/spaces.json`.
12. Migrated the browser to Next.js App Router with React and TypeScript in `app/`. React views own library, quiz, and flashcard interactions; `app/_study/study-app.tsx` owns shared selection state and refreshes from the API after saved actions. The hash-based last-space selection, partial quiz/flashcard generation success, legacy open-ended runs, and request-usage details remain supported.
13. Kept the Next route shell (`layout.tsx`, `page.tsx`, and global CSS) at the root of `app/` and grouped the study implementation in the private `app/_study/` folder. The server route structure matches its workflows. The library owns its native dialog mechanics, the space selection path shares one state update, and flashcard edits use the normal API refresh path so the current review face updates.
14. Moved the HTTP API into a Next.js Node.js Route Handler at `app/api/[...path]/route.js`. The workflow modules now accept Web `Request` objects and return Web `Response` objects, with `app/api/_server/index.js` dispatching and handling errors. Browser URLs, response shapes, model calls, validation, legacy endpoints, and `data/spaces.json` remain the same. Removed the `/api` rewrite, API port configuration, and two-process launcher. `npm run dev` and `npm start` now launch only Next.js. The JSON store is still suitable only for one process with persistent local disk; the route migration does not make it safe for multi-instance or serverless hosting.
15. Moved the server-side API modules from the top-level `server/` directory into the private `app/api/_server/` directory. This is a code placement cleanup; Next.js already ran the modules through the Route Handler. The store's default path was adjusted so existing root `data/spaces.json` is reused without migration. After the move, `npm test`, `npm run typecheck`, and `npm run build` passed; a production-style GET of `/api/spaces` returned the existing saved spaces.
16. Adopted Material UI for the browser UI. `app/layout.tsx` wraps the app in the recommended Next App Router Emotion cache and shared theme. The Library uses a Drawer with Material UI list and form controls; workspace actions, study mode buttons, quiz answers, flashcard editing and review, saved-run pickers, status messages, and secondary disclosures use Material UI controls. The custom study logic and API shapes remain unchanged. The small create-space and add-document reveal controls and the native file input remain native. Global CSS element rules were scoped away from Material UI controls. The UI test now provides browser globals used by Material UI and checks the Drawer rather than a native `<dialog>`.
17. Replaced the all-width modal Library with a traditional responsive sidebar. The header menu icon is on the left. At 900px and wider, Material UI's persistent Drawer opens by default and shifts the workspace; selecting a document leaves it open. Its 240–480px resize edge supports pointer drag, Left/Right arrows, Home/End, and double-click reset to 300px; the width persists in local storage. On smaller screens the Drawer remains modal and document selection closes it. Closing the desktop sidebar returns focus to the menu trigger. `study-app.tsx` owns the responsive open and width state, while `library.tsx` owns the resize interaction.
18. The navigation now has two steps: searchable spaces list, then the space's study workspace. `study-app.tsx` owns navigation and selected source preview state; `library.tsx` owns the spaces list and optional Sources panel. `#space-id` opens the workspace; `#space-id/study` remains an alias and `#space-id/document-id` opens the source preview within it. A hash without a valid space returns to the spaces list.
19. New space and Add document reveal their forms only when needed. The study header shows the space title and generation actions; the optional Sources drawer overlays from the right and contains document search, upload, and a read-only list. Document preview is deferred.

## Server and storage decision status

The storage and hosting choices below remain open after the HTTP route migration.

| Topic | Current implementation | Discussed direction and status |
| --- | --- | --- |
| HTTP API | Next.js Node.js Route Handlers serve `/api` in the same process as the browser app. | The separate API process and rewrite have been removed. **Implemented.** |
| Study data | `app/api/_server/store.js` saves document text, generated material, API request bodies, and study history in local `data/spaces.json`. Writes are serialized only within this process. | Managed PostgreSQL was considered for a hosted multi-user app. Browser-local IndexedDB with export/import was considered to avoid server-side retention of readable study data. Neither replaces the current store yet. **Open.** |
| Sync and recovery | Saved work is available on the local server only. There are no accounts or data export/import controls. | Optional client-encrypted sync could provide multi-device recovery while the sync service stores ciphertext. It would require accounts, key recovery, conflict handling, and a clear explanation of what metadata remains visible. **Open.** |
| AI data flow | The server sends selected document text to OpenAI for generation with `store: false`; the app also saves source text and the exact request body locally. | A future stateless endpoint could stop *this app* from persisting material, but generation would still send readable text through the server to OpenAI. No on-device model or no-retention guarantee has been chosen. **Open.** |
| Public deployment | Local prototype served by Next.js on port 3000; no authentication. Per-space deletion is available. | Hosting, storage, access control, deletion guarantees, backups or export, and operational limits must be designed together before inviting public users. **Open.** |

Do not describe local-first storage, encrypted sync, or zero data retention as existing features. Revisit these alternatives when choosing the first hosted release's privacy and recovery requirements.

# Adaptive study-bank evaluation

Status: **all six generation cases and provisional agent reviews completed; human review pending**. This experiment asks whether 40K and 100K spaces can produce a sufficiently complete, accurate bank of study material when the total number of questions and cards follows the content rather than a fixed cap. It uses the same frozen frontend, Java, and systems/AWS source sets and the same approved reference concepts as the earlier pilots. The app's product limit and saved data remain unchanged. Findings and limits are in [RESULTS.md](RESULTS.md).

## Method

Use `gpt-6.1-terra` at medium reasoning effort. For each of the five frozen documents, make a separate source-backed concept extraction request. Ask for every distinct, assessable idea with an exact evidence quote and source block ID. Do not supply the approved reference concepts or previous outputs to generation. A document's extracted concepts determine its candidate output count; there is **no ten-question, twenty-card, or fixed per-document total**. Operational token limits apply to each API response, and an incomplete response is a recorded failure, never silently treated as full coverage.

Generate study material in small batches of extracted concepts. Produce an idea for each concept and a quiz question or flashcard when the concept is suited to that format; both are allowed. Validate citations, required fields, concept IDs, and duplicate text. Store all items in a bank, then group questions and cards into manageable sessions without discarding any items. The session size affects presentation only and is not a generation or evaluation cap. A case succeeds only when all five documents, concept batches, and output validation complete.

The extraction is a source-derived inventory, not the evaluation gold set. It may miss concepts or invent unsupported claims. Reviewers must score the bank against the independent approved reference concepts and source passages. The generated count and the number of distinct correct concepts it covers are both outcomes, not targets chosen after seeing the result.

## Matrix and controls

`3 source sets × 2 sizes × 1 run = 6 cases`, each with Main ideas, Quiz, and Flashcards banks. Use `frontend-40k-terra-adaptive-r1` style case IDs. Run sequentially; never regenerate a completed case or conceal failed calls. Keep the model, frozen source hashes and order, source-block construction, scoring rubric, and reviewer procedure fixed across sizes. The method changes both processing and output policy from the earlier capped pilots, so their results are historical reference, **not a controlled estimate of which change caused an effect**. A second full repetition is conditional on the first six cases passing feasibility checks.

Use the earlier approved coverage gates as first-pass quality checks: Main ideas at least 70% overall and 80% high-priority, Quiz 35%/50%, Flashcards 50%/60%. Each format also needs at least 95% correct and supported items, zero serious errors, mean usefulness at least 1.3, and a validated result. Report coverage of the union across all formats, item counts, duplicates, source/document/third balance, first and final success, total attempts, user-level wait, total USD cost, and cost per distinct accurate high-priority concept. Keep raw numerators and denominators. The prior 180-second wait gate is reported but may not be realistic for building an entire bank; decide on a whole-bank wait target from measured results before product adoption. The runner uses a self-imposed $2 case ceiling and $25 stage ceiling, matching the previous pilot's limits as a conservative guardrail for this authorized test. Stop before exceeding either; unknown-cost calls require a conservative reservation and explicit accounting.

## Artifacts and review

Tracked harness and prompts live in `evaluations/adaptive-bank/`. Private corpus, requests, outputs, scores, progress, and reviews live only in ignored `data/evaluation/experiments/adaptive-bank/`. Each case needs `manifest.json`, `calls.json`, `outputs.json`, `scores.json`, and `report.md`. The manifest records prompt/schema/code versions and source hashes. Calls include every attempt, validation outcome, usage, known cost or unknown reason, and elapsed time. Outputs include the complete extracted inventory, generated bank, and any explicit failures. Scores remain provisional until reviewed.

After generation, prepare method-blinded packets and score each case with the existing concept-coverage, accuracy, usefulness, and balance rubric. Have two independent agent reviews of one 40K and one 100K packet before scoring the remainder; preserve disagreements and reconcile against source passages. Do not treat source citations or schema validation as proof of quality. No product-limit change follows from this one exploratory repetition alone.

## Run record, 2026-11-20

All six cases generated validated banks from the frozen corpus. The isolated runner made 232 recorded API calls with $3.0119052 in known standard-rate cost and no unknown-cost attempts. Three cases completed without a validation interruption; three 40K cases required preserved local validation fixes or a recorded retry. Every case has the five required private artifacts. At generation completion, thirty anonymous document packets were ready for review. The Java data-structures document has no approved reference concepts, so its coverage is unscorable until that reference gap is filled. Its items remain eligible for accuracy and usefulness review.

During the run, the local validator was amended to respect Java case-sensitive answer options, source quotes crossing adjacent numbered blocks, Markdown-escaped asterisks, and display-only block labels. Saved responses were revalidated locally where the underlying source words were present; the original failed call judgments remain in `calls.json`. The systems 40K storage extraction had five genuinely noncontiguous or altered quotes, so it was rejected and retried once with the same prompt. One frontend 40K generation response was lost to a runner initialization bug; that paid attempt remains recorded as a runner error and was regenerated. These interventions affect first-attempt reliability and wall time and are not hidden from the comparison.

`node evaluations/adaptive-bank/run-case.mjs --self-test` verified source hashes, queue, request isolation, and validation behavior without API calls. `npm test` passed all 20 tests after JavaScript changes. `python evaluations/adaptive-bank/build-review-packets.py` produced 30 packets; `python evaluations/adaptive-bank/summarize.py` produced the private structural summary. The review prompt and completeness checker are in this directory. The app's 40K limit and generation routes were not changed.

## Provisional review record, 2026-11-23

The user chose to review all generated items sequentially with agents. Thirty document packets now have 32 complete, machine-validated agent reviews: one primary review per packet and independent overlap reviews for one matched 40K/100K frontend document pair. The overlap agents agreed on concept credit and correctness but differed on 26 subjective usefulness ratings. A separate agent adjudicated all six serious flags against the source passages. Four remain serious; Q230 is a minor wording issue with a valid key, and Q296 is correct and supported. The original reviewer judgments are preserved. The adjusted aggregate is `data/evaluation/experiments/adaptive-bank/review-aggregate.provisional.json`, and the tracked findings are in [RESULTS.md](RESULTS.md). The original case `scores.json` files remain pending human review.

A source/reference audit found one approved systems 40K concept whose evidence extends past the frozen source boundary. The adjusted aggregate excludes it from that case's denominator and records the exclusion; the original reference and review stay intact. Java data structures still has no approved reference concepts. These gold-set limitations and one run per case prevent a confident character-limit decision. All six complete study sets miss at least one predeclared quality gate, primarily because one idea per extracted concept is too shallow. A second identical repetition is not warranted before changing the summary policy. No product behavior, character limit, or saved study data changed. `npm test` passed all 20 tests after the final JavaScript change; the Python review scripts compiled and all 32 review files validated.
